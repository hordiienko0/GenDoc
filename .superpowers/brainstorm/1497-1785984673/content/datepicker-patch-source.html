Дата-пікер (квадратний календарик) — готовий патч

«Військовий облік v4 - standalone.html» перевищує 256 KiB, тому MCP-читання файлу обрізається на середині (десь у секції клас-методів після getters). Повний безпечний перезапис файла звідси неможливий без ризику втратити «хвіст» файла, якого я не бачив. Цей файл містить усе, що потрібно вставити вручну в основний файл (5 локацій + стан/методи компонента) — підтверджено з макета, розміри й кольори взято 1:1 з дизайн-системи проєкту (--navy/--accent/--border/--panel).

1. Додати в state = {'{'} ... {'}'} (клас Component, поруч з іншими полями)

datePickerFor: null,  // ключ поля, чий попап-календар зараз відкритий, або null

2. Додати в блок computed-геттерів (поруч з isTemplates, isGeneration тощо)

dpOpenNaboryStart: s.datePickerFor==='naboryStart',
dpOpenNaboryEnd: s.datePickerFor==='naboryEnd',
dpOpenTripStart: s.datePickerFor==='tripStart',
dpOpenTripEnd: s.datePickerFor==='tripEnd',
dpOpenImportStart: s.datePickerFor==='importStart',
dpOpenGenDoc: s.datePickerFor==='genDoc',

3. Додати методи класу (поруч з onToggleErrors — той самий паттерн toggle-стану)

onToggleDpNaboryStart() { this.set({ datePickerFor: this.state.datePickerFor==='naboryStart' ? null : 'naboryStart' }); }
onToggleDpNaboryEnd()   { this.set({ datePickerFor: this.state.datePickerFor==='naboryEnd'   ? null : 'naboryEnd'   }); }
onToggleDpTripStart()   { this.set({ datePickerFor: this.state.datePickerFor==='tripStart'   ? null : 'tripStart'   }); }
onToggleDpTripEnd()     { this.set({ datePickerFor: this.state.datePickerFor==='tripEnd'     ? null : 'tripEnd'     }); }
onToggleDpImportStart() { this.set({ datePickerFor: this.state.datePickerFor==='importStart' ? null : 'importStart' }); }
onToggleDpGenDoc()      { this.set({ datePickerFor: this.state.datePickerFor==='genDoc'      ? null : 'genDoc'      }); }

5. Точки застосування в «Військовий облік v4 - standalone.html»

Замінити відповідний <input value="..."> на шаблон із п.4 (DPKEY вказано для кожного):

5.1 Набори — модалка «Новий набір»

Було:  <input value="01.03.2027" style="width:100%; box-sizing:border-box; padding:7px 10px; ...">
DPKEY: naboryStart

Було:  <input value="31.05.2027" style="...">
DPKEY: naboryEnd

5.2 Швидке оформлення — модалка «Відрядження»

Було:  <input value="03.08.2026" style="...">
DPKEY: tripStart

Було:  <input value="07.08.2026" style="...">
DPKEY: tripEnd

5.3 Імпорт — крок «Призначити в набір»

Було:  <input value="01.03.2027" style="...">  (поруч з полем «Номер набору»)
DPKEY: importStart

5.4 Шаблони — рядок мапінгу {{дата_початку_набору}}

Тут немає текстового поля з датою — лише dropdown-мапінг поля бази. За рішенням з бренштормінгу іконка ▦ тут відкриває вибір ФОРМАТУ дати (дд.мм.рррр / дд місяця рррр / рррр-мм-дд), а не значення. Додати статичну квадратну кнопку праворуч від рядка мапінгу з title="Формат дати" (повноцінний dropdown формату — окрема майбутня ітерація, не блокує решту патчу).

5.5 Генерація — нове поле «Дата документа»

Це НОВЕ поле (наразі в блоці genForm його немає) — додати одразу після блоку «Пакет документів» (dropdown docPackages) і перед підсумковим блоком packageContents, зі своїм лейблом: 

<div style="font-size:11px; font-weight:700; text-transform:uppercase; letter-spacing:0.05em; color:var(--dim); margin-bottom:5px;">Дата документа</div>
<!-- сюди фрагмент з п.4, DPKEY: genDoc, VALUE = сьогоднішня дата (dd.mm.yyyy), звичайне редаговане поле -->

Значення за замовчуванням — поточна дата на момент відкриття форми генерації; поле лишається звичайним редагованим текстовим полем (не readonly), користувач може ввести іншу дату або обрати в календарику. Підставляється в плейсхолдер {'{{'}дата{'}}'} згенерованих документів.

Примітка

Сітка днів у попапі — статичний мокап (як у затвердженому прев'ю), без реальної логіки обчислення місяця/днів і без запису обраного дня назад у поле — цього достатньо для дизайн-огляду. Повноцінна логіка вибору дня — окрема задача під час реалізації в реальному застосунку.
