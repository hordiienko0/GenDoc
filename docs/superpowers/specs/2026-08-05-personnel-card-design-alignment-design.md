# Особовий склад: підгонка під макет v4 (design doc)

Дата: 2026-08-05
Джерело макета: claude.ai/design проєкт `d291e112-a17f-4d57-91a4-1e5de26a7d03`,
файл `Військовий облік v4.dc.html` (читати через DesignSync `get_file`; файл
`... - standalone.html` — лише bundler-обгортка, не сам дизайн).

## 1. Контекст і мета

Екран «Особовий склад» (дерево підрозділів + список + картка людини)
реалізований 2026-07-26 за тим самим макетом. Порівняння поточного стану з
макетом виявило три групи розбіжностей — цей документ фіксує узгоджений план
їх усунення. Секції нижче впорядковані за пріоритетом, який задав користувач.

## 2. Косметичні правки

Кнопка `AddCommand` у списку: текст «+ Додати» → «+ Додати запис»
(`PersonnelView.xaml`), відповідно до макета. Інших текстових розбіжностей у
списку/дереві/футерах не виявлено.

Банер масового вибору (`Обрано N`, «Перемістити до…», «Видалити», «Зняти
вибір») лишається без змін — кнопка «Видалити» відсутня в макеті, але
користувач підтвердив, що вона потрібна і має залишитись.

**Правило проти дублювання:** перед додаванням будь-якого нового елемента UI
(кнопки, поля, панелі) — спершу перевірити, чи функціонально еквівалентний
елемент вже є на екрані. Якщо є сумнів — питати користувача, а не додавати
дубль.

## 3. Режим редагування вкладки «Дані»

Зараз усі поля картки завжди редаговані (`TextBox`/`ComboBox`), збереження —
кнопкою «Зберегти» внизу. Потрібен явний перемикач перегляд/редагування.

- `PersonCardViewModel` отримує `[ObservableProperty] bool IsEditing`,
  скидається в `false` при кожному відкритті картки (`LoadAsync`/`Initialize`).
- Поля рендеряться як `TextBlock` (read-only) коли `!IsEditing`; як зараз
  (`TextBox`/`ComboBox`) коли `IsEditing` — перемикання видимості двох
  представлень одного значення через `BoolToVisibility`/`InverseBoolean`, без
  дублювання логіки збереження.
- Нова кнопка «Редагувати» (олівець, поруч із заголовком картки) →
  `IsEditing = true`.
- «Зберегти»: як зараз (валідація, `IRecipientService.Save` через
  `RecipientEditModel`-подібний шлях, наявний у `PersonCardViewModel`), плюс
  після успіху `IsEditing = false`.
- «Скасувати»: якщо `IsEditing` — відкат незбережених змін (перезавантажити
  поля з моделі) і `IsEditing = false`, без закриття картки. Якщо не в режимі
  редагування — поточна поведінка (закриття картки/навігація) без змін.
- Dirty-guard (запит на підтвердження при навігації з незбереженими змінами)
  лишається без змін — `IsDirty` і так може стати `true` лише в режимі
  редагування.

## 4. Вкладка «Документи» — функціональна реалізація

Зараз: `PersonCardViewModel.LoadDocumentsAsync` показує пласку хронологічну
історію (`IPersonnelService.GetDocumentsAsync`) без статусів і дій, з
заглушкою «документи з'являться після реалізації архіву». Потрібно замінити
на статус-орієнтований список за шаблонами пакета — як у макеті.

### 4.1 Джерело пакета

Без окремого селектора в картці (макет його не містить). Використовується
`ICompletenessService.GetDefaultPackageIdAsync()` — той самий метод, що вже
рахує бейдж комплектності (глобальний дефолт з `AppSettings`, або перший
пакет за алфавітом, якщо дефолт не заданий). Футер вкладки (`cardIntakeNote`)
явно показує назву застосованого пакета (і назву набору, якщо
`Recipient.IntakeId != null`) — щоб оператор бачив контекст без пікера.

### 4.2 Новий сервісний шар

Додати в `ICompletenessService`/`CompletenessService` (без дублювання логіки
матриці — фокусовані методи для одного `recipientId`):

```csharp
public record RecipientDocStatus(
    int TemplateId, string TemplateName,
    int? DocumentId, int Version, bool HasContent, bool IsStale);

Task<List<RecipientDocStatus>> GetRecipientStatusAsync(int recipientId, int packageId);

Task<(int Generated, int Skipped, List<string> Errors)> GenerateMissingForRecipientAsync(
    int recipientId, int packageId, Dictionary<string, string> manualValues);
```

`GetRecipientStatusAsync` — бере список шаблонів пакета (перевикористати
наявний `GetPackageLinksAsync`), для кожного викликає вже існуючий
`GetCellAsync(recipientId, templateId)` і мапить у `RecipientDocStatus`
(документа немає → `DocumentId = null, Version = 0, HasContent = false,
IsStale = false`).

`GenerateMissingForRecipientAsync` — по кожному шаблону з `HasContent =
false` викликає наявний `GenerateForPairAsync(recipientId, templateId,
manualValues)` (той самий примітив, що вже використовує
`CompletenessViewModel.GenerateMissingAsync` для всієї матриці, і мій
нещодавній ad-hoc-шлях у Staff). Помилки збираються, не переривають цикл.

### 4.3 UI вкладки «Документи»

- Кнопка вгорі «Сформувати повний пакет»: викликає
  `GenerateMissingForRecipientAsync` для всіх бракуючих шаблонів. Неактивна
  (замінена на напис «Пакет повний», за аналогією з матрицею), якщо
  бракуючих немає.
- Якщо в шаблонах пакета є Manual-теги — перед генерацією (і масовою, і
  поштучною) відкривається наявний `ManualValuesDialogViewModel`
  (`ViewModels/Archive`) — не створюється новий діалог.
- Список `RecipientDocStatus`, по одному рядку на шаблон:
  - Назва шаблону (жирний).
  - Бейдж стану: «Є» (ok/зелений), «Немає» (dim/сірий), «Застарів»
    (warn/жовтий) — ті самі кольори, що в легенді матриці комплектності.
  - Meta-рядок: версія + (якщо є) дата останньої генерації.
  - «Відкрити» — видима лише якщо `HasContent`; викликає наявний
    `IDocumentArchiveService.OpenAsync(documentId)`.
  - Друга дія: «Згенерувати» (якщо `!HasContent`) або «Перегенерувати» (якщо
    `HasContent`; акцентний колір коли `IsStale`, приглушений — коли
    актуальний) → `GenerateForPairAsync` для цього одного шаблону.
- Футер: `cardIntakeNote` — «Пакет: {назва} · Набір: {назва набору}» (або без
  частини про набір для постійного складу).

### 4.4 Помилки

Одна невдала генерація (в масовій чи поштучній дії) не повинна ламати решту —
збирати помилки в список і показати короткий підсумок (як у
`CompletenessViewModel.GenerateMissingAsync`/`ArchiveViewModel.RegenerateAsync`),
а не кидати виняток нагору.

## 5. Тестування

- Юніт-тести на `CompletenessService.GetRecipientStatusAsync` (шаблон
  присутній/відсутній/застарілий) і `GenerateMissingForRecipientAsync`
  (генерує лише бракуючі, пропускає наявні, збирає помилки при частковому
  фейлі, не падає коли Manual-теги відсутні).
- Ручна перевірка в застосунку: відкрити картку людини з наявними й
  відсутніми документами пакета, натиснути «Сформувати повний пакет»,
  переконатись, що архів отримує нові версії й бейдж комплектності на інших
  екранах узгоджений.

## 6. Поза межами цієї роботи

- Селектор пакета всередині картки (макет його не передбачає).
- Зміни до дерева підрозділів, списку осіб, банера масового вибору (крім
  тексту кнопки «+ Додати запис») — уже відповідають макету.
- Розділи макета поза «Особовий склад» (Постійний склад, Набори, Матриця,
  Імпорт) — не в фокусі цього запиту.
