# Конструктор шаблонів (design doc)

Дата: 2026-08-12
Джерело макета: claude.ai/design проєкт `d291e112-a17f-4d57-91a4-1e5de26a7d03`,
файл `Конструктор шаблонів.dc.html`.

## 1. Мета

Дати змогу скласти шаблон документа прямо в застосунку — з готових блоків, —
щоб не редагувати `.docx` руками у Word і не вгадувати, які `{{теги}}` система
розпізнає. Підзаголовок у макеті формулює це прямо: «Складання документа з
блоків без ручного редагування .docx».

Це прямо продовжує наскрізну вимогу: максимум даних з системи, ручного вводу —
мінімум. Зараз оператор мусить знати перелік тегів напам'ять; конструктор
перетворює цей перелік на клікабельну палітру.

## 2. Розкладка (з макета)

Три колонки під двома вкладками режиму — **Документ Word** / **Відомість Excel**.

**Ліворуч (260 px) — палітра.**
- «Додати блок»: Шапка (гриф), Заголовок, Абзац, Таблиця, Підписи, Дата і місто.
- «Поля», згруповані: «Про людину», «Про частину», «Вручну при генерації»
  (остання група позначена застережливим кольором).
- Клік по полю вставляє мітку в позицію курсора (підказка в макеті:
  «Клік по полю в лівій панелі вставить мітку в позицію курсора»).

**У центрі — Документ.** Впорядкований список блоків-карток. У кожної картки
заголовок з типом блока і дії `↑ ↓ ✕`. Блок під редагуванням підсвічений
акцентною рамкою й підписаний «Абзац · редагується». Внизу — пунктирна картка
«+ Додати блок».

**Праворуч (340 px) — попередній перегляд.** Селектор «Тестова особа», далі
сторінка в Times New Roman із підставленими значеннями. Легенда внизу:
акцентна заливка — «з бази», застережлива — «вручну при генерації».

**Нижня смуга.** «Назва шаблону» + кнопки «Експорт у docx» і «Зберегти шаблон».

## 3. Як це лягає на наявну архітектуру

Ключове рішення: **конструктор не заводить окремий канал генерації.** Він
виробляє звичайний `.docx`, який зберігається в наявну сутність `Template`.
Тоді генерація, комплектність і архів працюють без жодних змін — конструктор
стає ще одним способом *отримати* шаблон, поряд із завантаженням файлу.

- **Емісія `.docx`** — `DocumentFormat.OpenXml` 3.5.1 уже в залежностях
  (використовується для читання/підстановки), тож збирати документ з блоків
  можна тим самим пакетом.
- **Повторне редагування.** Розібрати `.docx` назад у блоки надійно неможливо.
  Тому поруч із байтами зберігаємо джерело — JSON блоків. Нова колонка
  `Template.BuilderJson TEXT NULL`: заповнена → шаблон відкривається в
  конструкторі; порожня → шаблон завантажений файлом, конструктор його не чіпає.
  Міграція — чергова версія схеми в `DatabaseSchemaInitializer`, з
  `AddMissingColumns` (пастка з пам'яті: `Ensure*Tables` створює таблицю лише
  коли її нема, тож колонку треба додавати безумовно).
- **Палітра полів будується з `PlaceholderTagMaps`**, а не хардкодиться:
  - «Про людину» — ключі `RecipientTagMap`;
  - «Про частину» — ключі `OrganizationTagMap`;
  - «Вручну при генерації» — усе, що `PlaceholderTagMaps.Classify` віднесе до
    Manual.
  Це закриває відому пастку: тег, якого нема в мапах, мовчки стає Manual і
  колонка порожня. Якщо палітра — це і є мапи, розбіжність неможлива за
  побудовою.
- **Manual-теги на генерації** вже обслуговує наявний `ManualValuesDialog` —
  нічого нового не треба.
- **«Повторювати рядок для кожної особи»** в блоці «Таблиця» — це вже
  реалізовані повторювані блоки в таблицях DOCX (`{{#…}}/{{/…}}`, гілка
  `docx-table-repeating-blocks`). Конструктор лише проставляє маркери, логіка
  готова.
- **Режим «Відомість Excel»** відображається на `ExportTemplate` з
  `UsesPlaceholders = true` (ClosedXML уже в залежностях). За групуванням, яке
  ми щойно зробили, такий шаблон стає в розділ «Шаблони документів».

## 4. Модель блоків

```csharp
public enum TemplateBlockKind { Header, Title, DateAndCity, Paragraph, Table, Signatures }

public record TemplateBlock(
    TemplateBlockKind Kind,
    string? Text,                 // Title / Paragraph — текст із {{тегами}}
    TableSpec? Table,             // лише для Table
    SignatureSpec[]? Signatures); // лише для Signatures

public record TableSpec(string[] Columns, TableRowSpec[] Rows, bool RepeatPerPerson);
```

Серіалізація — `System.Text.Json` у `Template.BuilderJson`. Версію формату
покласти в корінь (`"v": 1`), щоб потім не гадати.

## 5. Попередній перегляд

Рендериться не з `.docx`, а з тієї ж моделі блоків — інакше прев'ю відставало б
від документа. Підстановка: значення тестової особи з БД, Manual-теги
показуються плашкою «‹вводиться при генерації›». Дві заливки за легендою макета.

Тестова особа — з наявного списку отримувачів; за замовчуванням перша особа
активного набору.

## 6. Рішення (узгоджено 2026-08-12)

1. **Підписант — конкретна людина з постійного складу.** У блоці «Підписи» та в
   шапці-грифі посадова особа обирається зі списку постійного складу, а не
   вписується руками і не лишається тегом. У блоці зберігається `RecipientId`
   підписанта; у документ підставляються його звання й ПІБ на момент генерації
   (щоб зміна звання підхопилась сама). Це і є наскрізна вимога «максимум даних
   із системи» в дії.
2. **Перший зріз — Word.** Блоки Заголовок / Абзац / Підписи, палітра з мап,
   збереження у `Template` + `BuilderJson`. Excel-режим і таблиця з повторенням —
   наступним кроком, коли Word працюватиме.
3. **Живе всередині «Шаблонів».** Не окремий пункт меню: вхід із екрана
   «Шаблони», далі повноекранний конструктор за макетом.

## 7. Поза межами

- Розбір довільного завантаженого `.docx` назад у блоки.
- Довільне форматування (шрифти, відступи, стилі) — блоки мають фіксований
  вигляд за макетом.
