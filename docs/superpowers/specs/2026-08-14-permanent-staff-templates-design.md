# Шаблони для постійного складу

Дата: 2026-08-14. Гілка: `ui-design-alignment`. Вимоги — відповіді користувача,
не припущення.

## Проблема

Діалог документів постійного складу (`StaffDocDialogViewModel`) показує **всі**
шаблони підряд: `GetPerRecipientTemplates()` / `GetAllTemplates()`. Жодного
поняття «для кого шаблон» у моделі немає, тож оператор бачить там шаблони для
наборів, які до постійного складу не стосуються.

## Рішення

### 1. Аудиторія шаблону

Нове поле на `Template`. «Залочені» тут означає **видимість, не захист від
редагування** — рішення користувача:

- шаблон постійного складу видно ЛИШЕ в постійному складі;
- звичайний шаблон видно ЛИШЕ у звичайній генерації й пакетах.

Пропозиція: enum `TemplateAudience { Intake = 0, PermanentStaff = 1 }`, поле
`Template.Audience` зі значенням за замовчуванням `Intake` — тоді всі наявні
шаблони лишаються там, де були, а міграція нічого не ламає.

**Міграція v23.** ПАСТКА проєкту: колонку треба дописати В ОБИДВА місця —
у гілку версії ТА в безумовний `AddMissingColumns` наприкінці
`EnsureInitialized` (див. [[gendoc-conventions]], випадок `w.RawText`).

### 2. Розділ у «Шаблонах»

Окрема група в переліку шаблонів — поруч із наявним групуванням за
призначенням. Створення/редагування шаблону дозволяє вибрати аудиторію.

### 3. Постійний склад

`StaffDocDialogViewModel` показує лише `Audience == PermanentStaff`. Наявні
шаблони звідти **прибираються повністю** (рішення користувача: «прибрати
звідти всі»). Доки в новому розділі порожньо — порожній список із підказкою,
що шаблони для постійного складу заводяться в «Шаблонах», а не мовчазна
порожнеча.

Звичайна генерація й пакети, навпаки, мусять відфільтрувати
`Audience == PermanentStaff`, інакше «залочені» протечуть назад.

### 4. Індивідуальна форма під шаблон

**Нічого нового будувати не треба.** Форма вже будується з міток самого
шаблону: `ManualTagClassifier` + `ManualTagFormBuilder` дають дати пікером,
тексти з минулого разу і вибір підписанта. Різні шаблони мають різні мітки,
отже й форми різні — це і є «індивідуальна форма».

Треба лише переконатися, що діалог постійного складу проходить тим самим
шляхом (після правки 2026-08-14 він уже має спільну форму — перевірити наживо).

Потік: обрати кого → обрати шаблон → форма з його міток → генерація.

## Порядок

1. Модель + міграція v23 + тест на схему.
2. Фільтрація: постійний склад бачить лише свої, генерація й пакети — лише свої.
3. Вибір аудиторії в «Шаблонах» + окрема група в переліку.
4. Живий прогін.

## Не входить

- Захист шаблонів від редагування чи видалення (користувач обрав лише видимість).
- Редактор форм під шаблон (форма береться з міток).
