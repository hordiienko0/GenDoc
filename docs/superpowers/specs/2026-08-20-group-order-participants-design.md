# Учасники групового наказу: зв'язок «людина ↔ груповий документ»

Дата: 2026-08-20. Гілка: `ui-design-alignment`.
Продовження варіанта А (`2026-08-19-course-officer-quick-paths-design.md`).

## Задача

На БЗВП рапорти на зброю, стрільби тощо оформлюються **груповим наказом** на
весь склад (наприклад, 60 людей), а не індивідуальними документами. Сьогодні
груповий документ зберігає лише кількість людей і `RosterHash` — хто саме в
ньому був, ніде не записано. Тому «Комплектність» не може відповісти на
питання курсового: «чи покрита ця людина груповим наказом, і яким саме».

Рішення користувача (2026-08-20):
- участь = **склад на момент генерації** (пишеться автоматично, ручного
  редагування учасників немає);
- у «Комплектності» груповий шаблон — **колонка на особу**: «є» з посиланням
  на документ у тих, хто в чинному складі, «немає» в решти.

## Наскрізне обмеження

Як у попередніх спеках: нічого з функціоналу не прибирається. Це частковий
відкат пункту 1.4 з 19.08 (групові прибрали з матриці, бо клітинка була
беззмістовна) — тепер клітинка отримує зміст, і групові повертаються.

## 1. Дані

Нова таблиця:

```sql
CREATE TABLE "GeneratedGroupDocumentRecipients" (
    "Id" INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    "GeneratedGroupDocumentId" INTEGER NOT NULL
        REFERENCES "GeneratedGroupDocuments" ("Id") ON DELETE CASCADE,
    "RecipientId" INTEGER NOT NULL
        REFERENCES "Recipients" ("Id") ON DELETE CASCADE
);
CREATE INDEX ... ("GeneratedGroupDocumentId");
CREATE INDEX ... ("RecipientId");
```

- Модель `GeneratedGroupDocumentRecipient` + колекція
  `GeneratedGroupDocument.Recipients`.
- Міграція **v25**: ідемпотентне `EnsureGroupDocumentRecipientsTable` (патерн
  `EnsureGroupDocumentTables`) — і в гілці версії, і в безумовному хвості.
- Пишеться в усіх трьох місцях, де створюється `GeneratedGroupDocument`:
  XLSX-фаза `RunXlsxPhase`, групова DOCX-фаза `RunDocxGroupPhase`, вибіркова
  генерація (вона використовує `RunXlsxPhase`). Склад — рівно ті люди, що
  потрапили у файл (після фільтра придатності).
- Кожна **версія** документа має власний склад: перегенерація створює новий
  запис документа з новим складом; стара версія лишається зі своїм.
- Старі документи (до v25) складу не мають — це стан «склад не записано»,
  відрізняти від «нікого немає» за `RecipientCount > 0 && учасників 0`.
  Бекфіл неможливий (у `RosterHash` людей не відновити); після першої
  перегенерації зв'язки з'являться.

## 2. Комплектність

- `GetPackageLinksInternalAsync(includeGroup: false)` більше не викликається
  для матриці: `BuildAsync` включає групові колонки. `MatrixTemplateInfo`
  лишається як є (`IsGroup` уже є).
- Стан клітинки групової колонки на особу:
  - **є** — людина серед учасників чинного (`IsCurrent`) групового документа
    цього шаблона для цього набору (або «спільного», `IntakeId == null`, якщо
    свого немає — те саме правило, що в підвалі картки);
  - **немає** — чинний документ є, людини в складі немає, або документа немає;
  - **склад не записано** — чинний документ є, згенерований до v25
    (`RecipientCount > 0`, учасників нуль): показувати нейтральний знак «?»
    з підказкою «згенеровано до оновлення - перегенеруйте, щоб бачити склад»;
  - «застарів» для групових не обчислюється.
- Клік по клітинці «є» відкриває сам груповий документ (як «Відкрити» в
  «Архів → Групові»).
- `MatrixDocDto` розширюється прапорцем `IsGroup` і `RosterUnknown` (bool) —
  або окремим типом; вибрати простіше при реалізації, але без дублювання
  словника `Docs`.
- **Вимоги**: у «Вимогах пакета» груповий рядок знову отримує перемикачі
  «Обов'язк./Опційний/Не потрібен» (відкат частини 1.5); валідація і підсумок
  рахують групові нарівні з персональними. Позначка «груповий - формується на
  весь склад» лишається як пояснення поруч.
- «Згенерувати все, чого бракує» групові **не генерує** (їх формує екран
  «Генерація» або «Згенерувати документ…») — але бейдж і лічильники готовності
  рахують відсутню участь як неповноту, якщо шаблон обов'язковий.

## 3. Картка особи

Підвал «Групові відомості пакета» стає особистим:
- «Рапорт котлове ГРУПОВИЙ · у складі, в.8 · Відкрити»;
- «не входить до чинного складу» (документ є, людини немає);
- «ще не сформовано» (документа немає);
- «склад не записано - перегенеруйте» (документ до v25).

## 4. Архів → Групові

Нова дія «Учасники» (доступна при одному виділеному документі з записаним
складом): діалог зі списком складу цієї версії — звання, ПІБ, підрозділ.
Порожньо для документів до v25 — дія неактивна з підказкою.

## Тести

- Усі три фази генерації пишуть учасників (наскрізь, справжні шаблони).
- Перегенерація: нова версія зі своїм складом, стара — зі своїм.
- Матриця: «є» лише в учасників; «склад не записано» для легасі-документа.
- Картка: три стани підвалу.
- «Вимоги»: груповий рядок знову з вимогою, валідація рахує.
- Живий прогін на робочій базі: згенерувати відомість на частину складу,
  побачити «є/немає» в матриці, відкрити документ з клітинки, «Учасники».

## Порядок

1. Дані + запис у генерації (v25).
2. Комплектність (матриця + вимоги).
3. Картка особи.
4. Архів «Учасники».
Кожен крок — окремий коміт із тестами.
