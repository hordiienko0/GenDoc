# Варіант Б: «моє» для кількох курсових на одному ноутбуку

Дата: 2026-08-25. Гілка: `ui-design-alignment`.
Продовження варіанта А (`2026-08-19-course-officer-quick-paths-design.md`,
розділ «Що НЕ входить») і учасників групового наказу
(`2026-08-20-group-order-participants-design.md`).

## Задача

Курсових офіцерів кілька, кожен під своїм профілем на одному ноутбуку, у
кожного — свій набір. Сьогодні весь стан застосунку спільний: активний набір
один на всіх (чужий клік у «Наборах» збиває контекст), «Генерація» щоразу
починає з типового пакета, архів не відрізняє «моє» від чужого, а дати й
підписант «з минулого разу» — останні по застосунку, не по людині.

Рішення користувача (2026-08-25):
- активний набір — **свій у кожного профілю**;
- домашній екран «Мій набір» — новий розділ, але **стартовим лишається
  «Особовий склад»**;
- фільтр «Всі / Мої» в архіві — типово **«Всі»**, вибір пам'ятається на
  профіль;
- перекомпонування «Генерації» — **у цьому ж варіанті**.

## Наскрізне обмеження

Як у попередніх спеках: нічого з функціоналу не прибирається. Глобальні
налаштування (`AppSettings`) лишаються і працюють як fallback — застосунок з
одним користувачем поводиться так само, як досі.

## 1. Дані — міграція v26, таблиця `UserSettings`

```sql
CREATE TABLE "UserSettings" (
    "Id" INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    "UserProfileId" INTEGER NOT NULL UNIQUE
        REFERENCES "Users" ("Id") ON DELETE CASCADE,
    "ActiveIntakeId" INTEGER NULL REFERENCES "Intakes" ("Id") ON DELETE SET NULL,
    "LastPackageId" INTEGER NULL REFERENCES "GenerationPackages" ("Id") ON DELETE SET NULL,
    "ArchiveMineOnly" INTEGER NOT NULL DEFAULT 0,
    "LastManualValuesJson" TEXT NULL,
    "LastSignerByTemplateJson" TEXT NULL
);
```

- Модель `UserSettings` + `UserSettingsService`: `GetForCurrentUserAsync()`
  ліниво створює рядок для поточного користувача (`ICurrentUserContext`),
  окремі `Update*`-методи на кожне поле. Жодного кешу понад один запит — стан
  дрібний.
- Міграція **v26**: ідемпотентне `EnsureUserSettingsTable` за конвенцією
  (гілка версії + безумовний хвіст з `AddMissingColumns` повним переліком
  колонок).
- `LastManualValuesJson` / `LastSignerByTemplateJson` **читаються
  користувач-спершу**: значення з `UserSettings`, а якщо там порожньо —
  глобальні з `AppSettings` (перший вхід нового профілю бачить розумні
  дефолти). Пишуться тільки в `UserSettings`; глобальні поля в `AppSettings`
  лишаються й більше не оновлюються (fallback заморожується). Один читач
  (`ManualTagFormBuilder.RememberValues`/`Prefill`) — обидві гілки в одному
  місці.

## 2. Мій набір

Глобальний життєвий цикл набору (статус, дати, «день X з Y») не чіпається.

- `ActiveIntakeState.RefreshAsync`: спершу `UserSettings.ActiveIntakeId`
  (якщо такий набір існує і не архівний) → інакше глобальний
  `IIntakeService.GetActiveAsync()`, як сьогодні.
- Дія «Зробити активним» у «Наборах» тепер робить ДВА записи: глобальний
  прапорець активності (як досі — він лишається fallback-ом для профілів, що
  ще нічого не обирали) і `UserSettings.ActiveIntakeId` поточного профілю.
  Тобто чужий клік змінює глобальний fallback, але НЕ збиває тих, хто вже
  зробив свій вибір.
- Статус-бар («Активний набір: №4 · день 19 з 57») показує МІЙ набір.

## 3. Архів: «Всі / Мої»

- Перемикач «Всі / Мої» (двопозиційний, стиль сегментів як у «Вимогах») на
  всіх трьох вкладках архіву, поруч із наявними фільтрами; стан один на
  екран, живе в `UserSettings.ArchiveMineOnly`.
- «Мої»: Документи й Групові — `GeneratedByUserId == поточний`, Запуски —
  `RunByUserId == поточний`. Фільтрація в тих самих запитах сервісу
  (`DocumentArchiveService`), не в пам'яті.
- Легасі-записи без автора в «Мої» не потрапляють — це чесно: авторства немає.

## 4. Пам'ять останнього пакета

- Вибір пакета на «Генерації» пише `UserSettings.LastPackageId`.
- Порядок вибору стартового пакета («Генерація» і «Комплектність», один
  спільний метод — user-aware `GetDefaultPackageIdAsync`):
  1. `UserSettings.LastPackageId` (якщо пакет ще існує);
  2. глобальний `AppSettings.DefaultGenerationPackageId`;
  3. перший за алфавітом (як сьогодні).

## 5. Домашній екран «Мій набір»

Новий розділ угорі бічної панелі (іконка домівки вже є в «Кімнат» — взяти
інший гліф MDL2, `\uXXXX` за конвенцією). Стартовий розділ після входу —
«Особовий склад», як і був.

Вміст (усе з наявних сервісів, компонування карткою):
- картка набору: «Набір №4 · день 19 з 57 · 33 особи» (з
  `ActiveIntakeState` + лічильник осіб);
- готовність стартового пакета (той, що з п. 4): «бракує N» — той самий
  розрахунок, що живить бейдж навігації (`CountMissingAsync`), і кнопка
  «Згенерувати все, чого бракує» → перехід у «Комплектність»;
- мій останній запуск: дата · пакет · «згенеровано N» · «Показати в архіві»
  (перехід як у картці підсумку 2.4);
- швидкі дії: «Генерація», «Комплектність», «Архів».

Порожні стани: немає мого набору → «Оберіть набір у "Наборах"» з переходом;
немає запусків → «Запусків ще не було» з кнопкою на «Генерацію» (як 2.6).

## 6. Перекомпонування «Генерації»

Права панель пакета зараз — один наскрізний ScrollViewer: кнопка генерації й
картка підсумку опиняються нижче краю екрана.

- Grid `Auto / * / Auto`: зверху — заголовок «ШАБЛОНИ ПАКЕТА» з «Вимогами»;
  посередині — прокручувана частина (шаблони, особовий склад, дата, значення
  для генерації); знизу — закріплені тека документів, «Генерувати повторно…»,
  кнопка «Згенерувати…» і картка підсумку.
- Кнопка і підсумок видимі завжди, без прокрутки. Поведінка не змінюється —
  лише розкладка.

## Тести

- `UserSettingsService`: get-or-create (двічі поспіль — один рядок),
  оновлення кожного поля, каскад при видаленні профілю.
- Мій набір: fallback-ланцюжок (свій → глобальний → немає); вибір
  неіснуючого/архівного набору → fallback.
- Архів «Мої»: документи/групові/запуски фільтруються по автору; легасі без
  автора відсутні в «Мої», присутні у «Всі».
- Пакет: ланцюжок LastPackageId → DefaultGenerationPackageId → перший.
- Ручні значення: користувач-спершу, fallback на глобальні, запис лише в
  `UserSettings`.
- Домашній екран: VM збирає картку з тих самих чисел, що сервіси; обидва
  порожні стани.
- Розкладка «Генерації» — живий знімок (регресійних тестів на розкладку немає).
- Живий прогін: два профілі на одній базі — у кожного свій набір, свій
  останній пакет, свої дати/підписант; перемикач «Мої» в архіві.

## Порядок

1. v26 + `UserSettings` + сервіс (тести).
2. Мій набір (`ActiveIntakeState` + запис вибору).
3. Пам'ять останнього пакета + ручні значення користувач-спершу.
4. Архів «Всі / Мої».
5. Домашній екран «Мій набір».
6. Перекомпонування «Генерації».

Кожен крок — окремий коміт із тестами.
