# Зовнішні документи особи та вкладка «Усі» в Архіві

Дата: 2026-11-18. Гілка: `qa-2026-09-26`.

## Навіщо

До людини приходять документи, які програма не генерує: довідки, витяги,
скани рапортів з інших підрозділів тощо. Зараз їх нікуди прив'язати:
Архів зберігає лише пари «особа + шаблон» (`GeneratedDocument.TemplateId`
обов'язковий), а «Підгрузити версію» / «Прикріпити скан» працюють тільки
поверх уже згенерованого документа.

Потрібно:

1. Підгрузити зовнішній файл до особи з її картки (Особовий склад → картка →
   «Документи»).
2. Файл лежить в Архіві. З картки особи його видно, і звідти можна перейти
   до нього в Архів.
3. Вкладка «Документи» в картці показує, які документи на людину **реально
   є**, а не перелік шаблонів пакета набору.
4. Архів за замовчуванням відкривається на списку **всіх** документів
   (особисті, групові, зовнішні), щоб знайти потрібне одразу, без
   перемикання вкладок.

## Цілі / не-цілі / анти-цілі

**Цілі:** пункти 1-4 вище.

**Не-цілі:**
- Версії для зовнішніх документів (нова редакція = підгрузити ще один
  документ, старий видалити).
- Підгрузка з Архіву (там потрібен вибір особи). Підгрузка тільки з картки.
- Картка постійного складу (розділ «Постійний склад») - не чіпаємо.
- Типи/категорії зовнішніх документів, обов'язковість, облік у комплектності.
- Синхронізація бази ще не реалізована. Коли її робитимуть, нову таблицю
  треба буде включити (примітка для майбутнього, не для цієї роботи).

**Анти-цілі (провал, навіть якщо «працює»):**
- Зламана генерація, матриця комплектності, перевірка «застарів»,
  перегенерація чи історія версій.
- Архів помітно повільніше відкривається.
- Зовнішній документ «губиться»: є в базі, але не видно ні в картці, ні в
  Архіві, ні в Кошику після видалення.

## Підходи

| | Суть | Плюси | Мінуси |
|---|---|---|---|
| **А (обрано)** | Нова таблиця `ExternalDocuments` + вкладка «Зовнішні» в Архіві | Не зачіпає генерацію й комплектність, мінімальний ризик | В Архіві окрема вкладка (знято вкладкою «Усі») |
| Б | Зробити `TemplateId` необов'язковим, зберігати в `GeneratedDocuments` | Безкоштовно отримують версії, скани, кошик, пошук | Увесь код вважає, що шаблон є; великий ризик зламати генерацію |
| В | Окрема таблиця, показ в основному списку «Документи» | Один список | Фільтри «Шаблон»/«Пакет» не застосовні, пагінація по двох таблицях заплутана |

Користувач обрав **А** і додав вимогу: за замовчуванням Архів показує все
разом (вкладка «Усі»).

## Дизайн

### 1. Дані

Нова сутність `ExternalDocument` (`ISoftDeletable`), таблиця
`ExternalDocuments`, міграція схеми 34 → 35 (`CREATE TABLE` у
`DatabaseSchemaInitializer`, як для інших таблиць):

| Поле | Тип | Примітка |
|---|---|---|
| Id | int | |
| RecipientId | int | FK на особу |
| Title | string | назва документа, обов'язкова; за замовчуванням ім'я файлу без розширення |
| FileName | string | оригінальне ім'я файлу |
| Content | byte[] | вміст (база вже шифрована SQLCipher) |
| SizeBytes | long | |
| Note | string? | примітка, необов'язкова |
| IntakeId | int? | знімок набору особи на момент підгрузки |
| OrgPathSnapshot | string? | знімок шляху підрозділу (як у `GeneratedDocument`) |
| UploadedByUserId | int | |
| UploadedAt | DateTime | |
| DeletedAt / DeletedBy | | м'яке видалення → Кошик |

Вміст зберігаємо в тій самій таблиці (як `DocumentAttachment.Content`).
Списки читаються лише проєкціями без `Content`.

Ліміт розміру той самий, що й для інших файлів (`AppSettings.MaxDocumentSizeKb`,
`FileLimitErrorAsync`). Будь-який тип файлу (pdf, jpg, png, docx, xlsx…).

Журнал дій: «Підгружено зовнішній документ», «Відкрито зовнішній документ»,
«Змінено зовнішній документ», «Видалено зовнішній документ», «Відновлено
зовнішній документ» - з ПІБ особи й назвою документа в деталях.

### 2. Сервіс

Методи для зовнішніх документів додаються в `IDocumentArchiveService` /
`DocumentArchiveService` поруч із вкладеннями (або в окремий
`ExternalDocumentService` - на розсуд виконавця, якщо архівний сервіс стає
задовгим):

- `UploadExternalAsync(recipientId, filePath, title, note)`
- `UpdateExternalAsync(id, title, note)` - перейменувати / змінити примітку
- `OpenExternalAsync(id)` - через `ISecureTempFileService.OpenAsync`, як вкладення
- `PrintExternalAsync(id)`, `SaveExternalAsAsync(id, path)` - як для вкладень
  (з водяним знаком там, де він застосовується до вкладень)
- `DeleteExternalAsync(ids)`, `GetDeletedExternalAsync()`, `RestoreExternalAsync(id)`
- `QueryExternalAsync(filter)` - для вкладки «Зовнішні»
- `QueryAllAsync(filter)` - для вкладки «Усі» (див. нижче)
- `GetPersonDocumentsAsync(recipientId)` - для картки особи (див. нижче)

### 3. Картка особи → вкладка «Документи»

Замість переліку шаблонів пакета - перелік документів, які на людину **є**:

```
[ Підгрузити документ… ]  [ Згенерувати документ… ]

⚠ Бракує за пакетом: Рапорт про прибуття, Анкета   [Сформувати]   ← лише якщо бракує обов'язкових

РАПОРТ ПРО ПРИБУТТЯ                       Згенерований  в.2
12.11.2026 · Петренко О.
Відкрити · Друк · В архіві · Перегенерувати

ДОВІДКА ВЛК                                 Зовнішній
15.11.2026 · Іваненко П. · «оригінал у справі»
Відкрити · Друк · В архіві · Змінити · Видалити

СПИСОК НА ЗАБЕЗПЕЧЕННЯ                      Груповий  в.3
10.11.2026
Відкрити · В архіві

[ Усі документи особи в Архіві ]
```

- Особисті згенеровані: поточні версії (`IsCurrent`) за **будь-якими**
  шаблонами, не лише з пакета. Мітка «Застарів» зберігається.
  Дія «Перегенерувати» на рядку лишається (як зараз, через
  `GenerateForPairAsync` із ручними тегами), підсвічена, коли документ
  застарів. *(Рішення під час рецензії: не прибираємо щоденну функцію.)*
- Зовнішні: усі не видалені зовнішні документи особи.
- Групові: поточні групові документи, де особа є в складі
  (`GeneratedGroupDocumentRecipients`).
- Сортування: найновіші зверху.
- Рядок «Бракує за пакетом…» з кнопкою «Сформувати» - **рішення виконавця
  дизайну**: зберігаємо наявну функцію «Сформувати повний пакет», але
  компактно, одним рядком, і лише коли бракує обов'язкових документів.
  Перелік шаблонів пакета та підпис «Пакет: … · Набір: …» прибираємо.
- Попередження про групові прогалини (обов'язкова відомість без цієї особи,
  `HasGroupGaps`) лишається окремим рядком із наявною підказкою
  «Відомості формуються на екрані «Генерація» або в «Комплектності»»,
  без кнопки. *(Рішення під час рецензії: попередження не зникає.)*
- Порожній стан: «Документів ще немає. Згенеруйте або підгрузьте документ.»
- «В архіві» → Архів, вкладка «Усі», фільтр «Особа: ПЕТРЕНКО І.І.»,
  потрібний рядок виділено й прокручено до видимості.
- «Усі документи особи в Архіві» → те саме без виділення рядка.

**Діалог «Підгрузити документ»:** спершу стандартний вибір файлу, потім
маленьке вікно: «Назва *» (заповнено ім'ям файлу без розширення), «Примітка»,
кнопки «Скасувати» / «Зберегти». Після збереження список у картці
оновлюється. «Змінити» відкриває те саме вікно без вибору файлу.

### 4. Архів

Вкладки: **Усі** (нова, перша й типова) · Документи · Групові ·
**Зовнішні** (нова) · Запуски.

Підзаголовок «Уся згенерована документація з історією версій» міняємо на
«Уся документація: згенерована, групова й зовнішня».

**Вкладка «Усі»** - один список поточних версій трьох видів документів:

| ТИП | ПІБ | НАЗВА | ВЕР. | НАБІР | ДАТА | АВТОР |
|---|---|---|---|---|---|---|
| Особистий | ПЕТРЕНКО І.І. | Рапорт про прибуття | 2 | 3/2026 | 12.11.2026 | Петренко О. |
| Груповий | 24 особи | Список на забезпечення | 3 | 3/2026 | 10.11.2026 | Петренко О. |
| Зовнішній | ПЕТРЕНКО І.І. | Довідка ВЛК | - | 3/2026 | 15.11.2026 | Іваненко П. |

- Фільтри: Набір, Рік, «Всі / Мої», пошук (ПІБ, назва, ім'я файлу). Фільтри
  «Шаблон» і «Пакет» на цій вкладці не показуємо. Групові документи пошук
  знаходить за назвою та ім'ям файлу, **не** за прізвищами учасників - усі
  документи конкретної людини, включно з груповими, показує фільтр особи.
  *(Рішення під час рецензії: пошук лишається швидким і без «шуму».)*
- Фільтр особи (з'являється лише після переходу з картки): плашка
  «Особа: ПЕТРЕНКО І.І. ✕». Показує особисті й зовнішні документи особи та
  групові, де вона в складі. ✕ знімає фільтр.
- Сортування: дата, найновіші зверху. «Завантажити ще» порціями по 200, як
  на вкладці «Документи».
- Дії: подвійний клік / «Відкрити», «Друк», «Зберегти як…» і «Перейти до
  вкладки» (відкриває рядок на його рідній вкладці - Документи / Групові /
  Зовнішні - де є всі дії: версії, перегенерація, скани, видалення).
  Видалення й решта специфічних дій на «Усі» не дублюються.
  Фільтр особи існує лише на «Усі». «Перейти до вкладки» на рідній вкладці
  скидає фільтри (Набір, Шаблон, Пакет, Автор, Рік → «Всі»), для особистих і
  зовнішніх ставить у пошук ПІБ особи, довантажує сторінки, доки рядок не
  знайдеться, виділяє й прокручує до нього.
  *(Рішення під час рецензії.)*
- Об'єднання трьох джерел: кожне джерело береться з фільтром і
  `Take(skip + take)`, далі злиття за датою в пам'яті й `Skip/Take` - на
  розсуд виконавця, головне: не тягнути `Content` і не завантажувати весь
  архів.
- Порожній стан: «Документів ще немає» / «Нічого не знайдено. Змініть
  фільтри» - як на вкладці «Документи».

**Вкладка «Зовнішні»** - таблиця: ПІБ, НАЗВА, ФАЙЛ, НАБІР, ПІДРОЗДІЛ,
ДАТА, ХТО ДОДАВ, ПРИМІТКА, РОЗМІР. Фільтри: Набір, Рік, «Всі / Мої», пошук.
Дії: Відкрити, Друк, Зберегти як…, Змінити (назва/примітка), Видалити
(в Кошик). Підгрузки тут немає, лише підказка в порожньому стані:
«Зовнішні документи підгружаються з картки особи: Особовий склад →
картка → Документи».

**Перехід з картки:** новий payload
`ArchivePersonNavigationPayload(int RecipientId, ArchiveItemKind? Kind, int? ItemId)`
через наявний `NavigateToSectionMessage`; `ArchiveViewModel.ApplyNavigationPayloadAsync`
перемикає на «Усі», ставить фільтр особи, скидає інші фільтри (набір/рік
на «Всі», пошук порожній), виділяє рядок `Kind + ItemId`. Якщо ввімкнено
«Мої», перехід перемикає на «Всі» **лише для цього відкриття**, без запису
в `UserSettings.ArchiveMineOnly` - інакше документи, підгружені колегами,
були б сховані. *(Рішення під час рецензії.)*

Індекси вкладок зміняться (додаються «Усі» і «Зовнішні»). Наявний перехід
`ArchiveRunNavigationPayload` має й далі відкривати «Запуски».

### 5. Кошик

Нова секція «Зовнішні документи» (ПІБ, назва, ким і коли видалено,
«Відновити») - як наявні секції документів і вкладень.

### 6. Особа в кошику

Якщо особу видалено, її зовнішні документи залишаються в Архіві й показуються
так само, як згенеровані документи видалених осіб.

## Що лишається виконавцю

- Розбиття сервісу (один архівний сервіс чи окремий).
- Точна реалізація злиття для вкладки «Усі».
- Розкладка нових XAML-елементів у наявних стилях (`ArchiveTabStyle`,
  `ArchiveActionButtonStyle`, `CardTabStyle` тощо).
- Тести: міграція 34 → 35, підгрузка (ліміт розміру, назва за замовчуванням),
  м'яке видалення / відновлення, `QueryAllAsync` (злиття, фільтр особи,
  групові через склад), `GetPersonDocumentsAsync`, навігація з картки.
